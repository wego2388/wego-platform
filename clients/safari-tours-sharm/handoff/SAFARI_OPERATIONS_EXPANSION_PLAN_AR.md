## قواعد التنفيذ

- PostgreSQL/Wego هو مصدر الحقيقة الوحيد؛ الورق وPDF مخرجات منه وليسا قاعدة
  بيانات ثانية.
- كل مشروع عميل مستقل؛ لا بيانات أو حسابات أو جداول مشتركة مع Sharm To Go أو
  Sharm Divers Club.
- لا سعر أو تكلفة أو عمولة أو دين أو دفعة أو اسم مورد يتم اختراعه.
- لا يتم اعتبار الاسترداد منفذًا إلا بعد حقيقة Paymob المؤكدة.
- تعديل الأرقام المالية بعد اعتمادها يكون بعكس/تسوية موثقة، وليس مسح التاريخ.
- أقل صلاحية لازمة لكل وظيفة، مع سجل من فعل ماذا ومتى.
- الواجهة العربية والإنجليزية تستخدمان نفس الوظائف والبيانات، مع RTL/LTR
  حقيقيين؛ لا ننشئ داشبوردين منفصلين.
- الطباعة تخفي البيانات غير اللازمة وتوضح حالة المستند (`DRAFT` أو `FINAL`
  أو `CANCELLED`) وتاريخ الطباعة ومن طبعه.

في الكود واختباراتها المحلية نجحت. قبول الحزمة وDB+media restore لم يكتمل؛

**قبول OPS2-A:** نفس مسارات ERP ونفس طلبات API ونفس حدود الصلاحيات؛

الدخول وبعده وبدون فقد حقول النموذج. أسماء الرحلات التجارية تُعرض بالعربية
إذا أتاحها الكتالوج، وإلا تظل الحقيقة المتاحة كما هي. صفحات لم تترجم بعد
توضح أنها بالإنجليزية ويظل محتواها `lang=en/dir=ltr`؛ لا ندعي أن تعريب ERP
كامل بمجرد تعريب الـshell. اختبارات render/SSR ومقاسات 360/768/1024/1440،
مع lint/typecheck/Vitest/build وcontract check.

## المرحلة 3 — مركز النماذج والطباعة

### النماذج الأولى

- [ ] **Booking Voucher:** المرجع، الرحلة، الموعد، المشاركون، الالتقاط، حالة
  الدفع/الحجز، تعليمات العميل وQR آمن للرجوع للنظام.
- [ ] **Payment Receipt:** رقم مستند مستقل، ما تم تحصيله فعلًا، الطريقة، العملة،

- [ ] **Daily Run Sheet:** رحلة/ميعاد، إجمالي الضيوف، توزيع الفنادق، ملاحظات
  التشغيل والحساسية/القيود الضرورية فقط.
- [ ] **Pickup Manifest:** ترتيب الالتقاط، الفندق، الغرفة عند الحاجة، هاتف
  التشغيل، عدد الأفراد، السائق/العربية بعد التعيين.
- [ ] **Driver Sheet:** مشوار السائق ونقاط الالتقاط واتصال التشغيل؛ بدون أسعار
  بيع أو بيانات مالية لا يحتاجها.
- [ ] **Supplier Order:** الخدمة المطلوبة، العدد، التاريخ، السعر المتفق عليه
  إن كان معتمدًا، ومسؤول التأكيد.
- [ ] **Cancellation / Refund Form:** سبب، سياسة مطبقة، المبلغ المتوقع، حقيقة
  Paymob، المنفذ والمراجع والتوقيعات الداخلية.
- [ ] **Settlement Statement:** ما للمورد/السائق وما دُفع وما تبقى، مع فترة
  ورقم تسوية.

- [ ] رقم إصدار، وقت الإنشاء/الطباعة، منشئه، اللغة، وشعار معتمد.

## ما سأعتبره «نقطة أمان» للمرحلة القادمة

لن أقول إن التشغيل نضج لمجرد ظهور شاشات. نقطة الأمان تعني:

1. الحجز اليدوي لا يتجاوز السعة أو السعر المعتمد.
2. المستندات ناتجة من الحقيقة ولا يمكن أن تخفي الإلغاء أو حالة الدفع.
3. المورد والسائق والتكلفة لهم تاريخ وصلاحيات، ولا يتم حذف أثر مالي.
4. الربحية لا تظهر إذا كانت التكلفة ناقصة.
5. التسوية لا تُدفع مرتين ولها اعتماد واضح.
6. العربية والإنجليزية متكافئتان وظيفيًا.
7. الاختبارات والمراجعة والنسخ الاحتياطي والاسترجاع كلها بدليل.
