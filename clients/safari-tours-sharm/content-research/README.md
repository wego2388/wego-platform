# Safari Tours Sharm — legacy content source

- **Source:** [safaritourssharm.com](https://safaritourssharm.com/)
- **Captured:** 2026-09-27
- **Status:** `RESEARCH_ONLY_UNTIL_OWNER_VERIFIED`
- **Runtime dependency:** none

This directory preserves the business content and core product idea from the
old WordPress website so the new Wego Platform product can improve it without
losing it. The old HTML, CSS, JavaScript, WordPress theme, booking form, and
data model are not copied into the runtime application.

## Source snapshot

`legacy-wordpress-export.json` is generated by:

```bash
node scripts/export-safari-tours-legacy-content.mjs
```

The snapshot contains:

- every public WordPress page returned by the Pages API, with original HTML
  stored as data and a normalized text projection;
- all 30 published `tour` records plus the customer-visible text rendered by
  each tour page;
- all 34 booking dropdown choices (30 tour choices plus Mega Safari, Petra,
  single room, and double room);
- metadata and source URLs for all 437 WordPress media records;
- source timestamps and a SHA-256 snapshot digest.

The 1.8 MB JSON snapshot is deliberately versioned. It is historical audit
evidence from a mutable external website, not a disposable build artifact:
regenerating it later can produce different content even when the exporter
code has not changed. The unified quality gate validates its digest and its
unverified/rights-quarantine markers but never refreshes it from the network.
Only an explicit content-research task may regenerate and review the snapshot.

Every page and tour is stamped `contentApprovalStatus: UNVERIFIED_SOURCE`.
Every media record is stamped `rightsStatus: UNVERIFIED` and
`migrationStatus: NOT_SELECTED`, so downstream agents cannot mistake captured
source material for approved production content.

Media binaries are not copied automatically. Most legacy media has no useful
alt text or rights metadata. Assets must be deduplicated, matched to a tour,
rights-approved, renamed, optimized, and given localized alt text before they
can enter the new site.

## Core idea to preserve and improve

Safari Tours Sharm is a direct Sharm El Sheikh tour operator centered on:

- desert adventures and Bedouin experiences;
- Red Sea boat, snorkeling, diving, and water activities;
- shows, spa, and family experiences;
- Cairo, Luxor, Sinai, Dahab, and cultural excursions;
- airport transfers plus room/car requests;
- hotel pickup and human assistance through WhatsApp.

The new product improves this from a WhatsApp-only brochure into a verified,
multilingual catalog with real availability, server-owned pricing, online
payment, booking recovery, and a staff ERP. WhatsApp remains an assisted-sales
and fallback channel, not the system of record.

## Legacy facts that conflict or need proof

- The homepage says free cancellation until 24 hours before departure and a
  small fee inside 24 hours. The dedicated policy page says full refund only
  above 48 hours, 50% at 24–48 hours, and no refund below 24 hours. One policy
  must be approved, versioned, and attached to the booking snapshot.
- The About page claims operation since 2015 and names four team members.
  Company history, names, roles, and photos require owner confirmation.
- Three homepage testimonials have no Google/Tripadvisor URL or booking proof.
  They must not be published as verified reviews without provenance.
- Some pages contain inconsistent facts, currency formatting, names, spelling,
  durations, and inclusions. The old value stays in the snapshot for traceability
  but the new catalog publishes only normalized, owner-approved facts.
- Animal experiences require a separate welfare/commercial decision before
  promotion; their existence on the old site is not automatic approval.
- The legacy WordPress media library contains 437 records, mostly without alt
  text, ownership, consent, or per-tour mapping.

      capacity, schedule, pickup, inclusions, exclusions, restrictions, and
      cancellation policy.
- [ ] Separate `TOUR`, `TRANSFER`, `ROOM`, and `REQUEST_ONLY` inventory types.
- [ ] Rewrite concise EN copy while preserving verified meaning.
- [ ] Produce and human-review AR, RU, and IT translations.
- [ ] Approve media rights and localized alt text.
- [ ] Import approved records through WEGO-016-C; do not read this snapshot at
      runtime and do not seed production-looking records from tests.
- [ ] Rehearse draft → approved → published → suspended across ERP, API, and
      public website.

## Publication rule

`legacy-wordpress-export.json` is evidence of what the old public site showed,
not commercial truth for the new system. No agent may convert `VERIFY`,
`REQUEST_ONLY`, or conflicting content into an active bookable record without
owner approval and executable publication-readiness checks.
