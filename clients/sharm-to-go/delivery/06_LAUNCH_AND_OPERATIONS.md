# Phase 6 — launch and operations

## Owner/external inputs

- [ ] Production domain and DNS authority supplied.
- [ ] Hosting/server/account boundary supplied.
- [ ] Production email and WhatsApp ownership confirmed.
- [ ] Real photos/assets supplied with publication rights.
- [ ] Legal entity, privacy controller and required business disclosures approved.
- [ ] App-store owner accounts and final release identity supplied when needed.

## Production infrastructure

- [ ] Isolated Sharm To Go database, credentials and least-privilege role.
- [ ] TLS, secure headers and production reverse-proxy routing.
- [ ] Secret injection outside Git and secret-rotation procedure.
- [ ] Backup schedule and a proven restore rehearsal.
- [ ] Database migration deployment/rollback runbook.
- [ ] Health, logs, correlation ids, metrics and alerting.
- [ ] Rate limiting/abuse controls for public request endpoints.
- [ ] Staging environment with synthetic data and no production customer PII.

## Content and commercial readiness

- [ ] Every launch service passes publication/readiness gate.
- [ ] Prices, capacity/schedule, pickup, policies and inclusions revalidated.
- [ ] Every image has recorded rights evidence and localized alt text.
- [ ] Arabic/English parity reviewed by humans.
- [ ] 25+/3M+/5M+/24-7 claims have owner-retained substantiation.
- [ ] Contact paths are monitored during advertised support hours.
- [ ] No prototype/design-system links are exposed in production navigation.

## Privacy, legal and support

- [ ] Privacy/terms updated for real request data and analytics.
- [ ] Retention, export, correction and deletion procedures exist.
- [ ] Consent records match actual communications behavior.
- [ ] Support can locate a request by public reference safely.
- [ ] Incident, cancellation, outage and supplier-failure runbooks exist.
- [ ] Refund language exists only when payment/refund capability exists.

## Release gate

- [ ] Full repository quality gate green on the release commit.
- [ ] End-to-end staging journey passes across web, ERP and mobile.
- [ ] Accessibility/performance/SEO/security checks pass.
- [ ] Fresh-database migration and backup restore pass.
- [ ] Sharm Divers Club regression and isolation proof pass.
- [ ] Owner signs off launch catalog, copy and customer journey.
- [ ] Deployment is explicitly authorized and release evidence is recorded.

## Post-launch

- [ ] Monitor request creation/error/confirmation conversion.
- [ ] Review unanswered/expired requests and support load daily at launch.
- [ ] Validate analytics against ERP truth without sending PII.
- [ ] Capture customer feedback as evidence, not invented reviews.
- [ ] Prioritize fixes before adding another vertical.
