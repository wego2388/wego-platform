# Reference study and originality boundary

## Inputs reviewed

- [Egyptra](https://egyptra.pro/) public discovery and booking experience,
  including destination lists, filters, trip planner, cart/saved/manage-booking
  navigation and a representative service detail flow.
- The owner-provided screenshots and image paths from Downloads/Pictures.
- Existing local projects were considered only for architecture/UX lessons;
  Sharm To Go was not copied from a separate repository.

These sources are discovery references. They are not runtime, build or content
dependencies.

## Useful interaction ideas adapted originally

- A strong discovery hero with category/date/group intent.
- Category-led browsing before a large catalog exists.
- Rich future filters: date, category, price, duration, start time, guide
  language, difficulty and accessibility.
- Detail pages that separate highlights, included/excluded, preparation,
  pickup, option pricing, add-ons and provider responsibility.
- Saved items, compare and itinerary planning as later customer tools.
- A visible booking-management path and clear confirmation summary.
- Locale/currency controls designed as first-class customer context.

Sharm To Go changes the commercial flow where needed: it defaults to
request-to-confirm for partner services instead of implying instant inventory.

## Deliberately not copied

- Source code, HTML/CSS, layout measurements or component implementation.
- Logos, photos, videos, icons, reviews, ratings, descriptions or translations.
- Service names, provider claims, prices, discounts, availability or policies.
- “29 languages” or multi-currency claims before end-to-end support exists.
- Instant checkout where provider capacity has not been verified.

The current visual system is original: sea/sand palette, abstract code-native
marks, a clarity-first marketplace notice, and no externally sourced raster
asset.
